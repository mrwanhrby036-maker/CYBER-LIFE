# توثيق قاعدة البيانات — Firebase Realtime Database

المشروع يستخدم **Firebase Realtime Database** فقط، وليس Firestore. الخادم هو الكاتب الوحيد عبر Firebase Admin SDK / REST باستخدام بيانات اعتماد خدمة. الواجهة لا تكتب مباشرة في القاعدة، وكل عمليات القراءة التشغيلية تمر عبر FastAPI لتطبيق التفويض وتقليل القراءات.

## المبادئ

- فصل البيانات حسب الغرض: `users`, `teams`, `curriculum`, `progress`, `assessments`, `missions`, `mission_submissions`, `reports`, `achievements`, `audit_logs`, `platform_settings`.
- معرّفات ثابتة: `ch01`, `ch01_l01`, `mis01`, `lab01`, `tm_researcher`.
- بيانات المستخدم تحت `$uid` لتجنب قراءة القاعدة كاملة في لوحة الطالب.
- مفاتيح الإجابة في `assessment_keys` ولا تُعاد أبداً في واجهات الطالب.
- سجل التدقيق `audit_logs` للقراءة الإدارية فقط.
- القوائم المتحركة مثل النشاط وسجل الطرفية محدودة (20/100 عنصر) لتقليل التضخم.

## العقد المهمة

| العقدة | الغرض | القراءة | الكتابة |
|---|---|---|---|
| `users/$uid` | ملف المستخدم | صاحبها أو مدير | الخادم فقط |
| `admin_roles/$uid` | دور إداري موثوق | صاحبها أو مدير | الخادم فقط |
| `teams/$team_id` | الفريق الدائم | الأعضاء أو مدير | الخادم فقط |
| `team_names/$name` | حجز اسم فريد | لا أحد عميلياً | الخادم فقط |
| `curriculum/*` | المحتوى المنشور | مستخدم مصادق | الخادم فقط |
| `assessment_keys/*` | مفاتيح التصحيح | ممنوع عميلياً | الخادم فقط |
| `progress/$uid` | تقدم الطالب | صاحبها أو مدير | الخادم فقط |
| `assessments/$uid` | محاولات التقييم | صاحبها أو مدير | الخادم فقط |
| `mission_submissions/$uid` | حالة المهام والقرارات | صاحبها أو مدير | الخادم فقط |
| `lab_sessions/$uid` | جلسات المختبر | صاحبها أو مدير | الخادم فقط |
| `reports/$uid` | التقارير والمراجعة | صاحبها أو مدير | الخادم فقط |
| `achievements/$uid` | الإنجازات | صاحبها أو مدير | الخادم فقط |
| `audit_logs` | تدقيق الإجراءات | مدير فقط | الخادم فقط |

## الفهارس

القاعدة تستفيد من `.indexOn` في `audit_logs` عند الترتيب حسب `created_at` أو `actor_uid`. معظم قراءات الطالب تتم بمسار مباشر `/$uid` ولا تحتاج فهرساً ثانوياً. قوائم الإدارة تقرأ عقدة محددة ثم ترتب في الخادم؛ عند النمو الكبير يوصى بإضافة استعلامات REST مقيدة `orderBy/limitTo` أو تجميعات دورية.

## النشر

```bash
firebase deploy --only database --project hamo-8132e
```

يجب نشر `database/database.rules.json` عبر ملف `firebase.json` الذي يشير إليه، أو لصق القواعد في Firebase Console. لا تستخدم قواعد قراءة/كتابة عامة.

## النسخ الاحتياطي

فعّل النسخ الاحتياطي التلقائي لـ Realtime Database من Firebase Console، وصدّر نسخة قبل عمليات الزرع القسري `content-seed force=true`.
